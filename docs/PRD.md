# Tenfold 十日环｜产品需求文档

版本：v1.0
日期：2026-08-03
产品形态：Tenfold 十日机械盘
文档状态：用于原型、用户验证与工程评审

## 1. 产品摘要

Tenfold 把散落在聊天、IDE、日历、任务工具和脑中的项目输入，压缩成一个可完成的十日承诺。AI 负责减少选择，EDC 负责把每天的推进与停止时间变成身体可感知的边界。

一句话定义：

> 一个项目，十天；每天按下一枚，到点收手。

Tenfold 不是通用 AI 助手、智能手表或健康设备。它不鼓励生成更多任务，也不诊断或治疗所谓“AI 精神病”、注意力障碍或前额叶问题。

## 2. 背景与问题

### 2.1 用户问题

AI 提高了生成代码、文案和方案的速度，但目标用户的判断、收尾与休息速度没有同步提高。典型表现是：

- 同时打开多个项目、会话和工具；
- 生成速度快于优先级判断；
- 任务持续分叉，Definition of Done 不清楚；
- 晚上仍在“只改最后一点”，缺少可信停止边界；
- 手机通知既是提醒入口，也是再次分心的入口。

### 2.2 证据边界

- Microsoft Research 在 CHI 2025 研究中收集 319 名知识工作者的 936 个 GenAI 工作案例；更高的 AI 信心与更少的批判性思考自报相关。这是关联性问题证据，不证明 AI 造成脑损伤。
- Ward 等人的两项实验发现，仅让自己的手机处于身边就与可用认知容量降低相关。该研究支持“把边界移出手机”的方向，不证明 Tenfold 有治疗效果。
- 当前没有可审计的“高端科技 EDC”统一 TAM。市场判断必须用目标用户、场景频率、留存和支付实验自下而上建立。

完整来源见 [research/](../research/)。

## 3. 目标用户

### 3.1 首个 ICP

AI-native 项目推进者：

- 创始人、独立开发者、vibe coder、创作者或单人项目 owner；
- 每周多次使用生成式 AI 推进真实项目；
- 经常在晚间持续工作，已有或主动寻找停机工具；
- 愿意为高品质 EDC、效率工具或身份物件付费；
- 主要痛点是项目失控和难以收尾，而非需要更多提醒。

### 3.2 非首发用户

- 需要医疗诊断或临床治疗的人群；
- 主要诉求是运动、睡眠和生理监测的用户；
- 需要多人项目管理、工单、审批和复杂排期的企业团队；
- 只寻找普通 fidget toy、计时器或通知器的人群。

## 4. 产品目标与非目标

### 4.1 目标

1. 把所有输入收敛为一个十日目标、最多三个结果、今天一个动作。
2. 让用户无需打开手机即可感知十日剩余进度。
3. 建立“回来、完成、封存、恢复”四个低摩擦动作。
4. 与现有戒断 vibe coding App 协同，在 22:00 后停止新建和继续生成。
5. 即使离线或 AI 不可用，十日循环仍能工作。

### 4.2 非目标

- 在硬件上浏览任务列表、消息或日历。
- 常开录音、摄像、脑电或生理监测。
- 公开 streak、排行榜、惩罚、电击或羞耻提醒。
- 自动替用户决定人生目标或未经确认修改项目。
- 首版同时支持团队协作、健康平台、复杂插件市场和订阅内容库。

## 5. 产品原则

### 5.1 减法原则

- AI 输出上限小于输入：`1 个目标 / 最多 3 个结果 / 今天 1 个动作`。
- 新输入默认进入停车场，不自动打断当前十日周期。
- 产品优先完成和停止，不优化使用时长、消息数量或建议数量。

### 5.2 身体边界原则

- 进度必须能看见和摸到：完成一天后，一枚日珠物理下沉。
- 手机负责编辑与解释；硬件只保留少数确定动作。
- 提醒不能成为重新打开信息流的入口。

### 5.3 恢复原则

- 中断不清零、不补 streak、不惩罚。
- 用户有 24 小时恢复窗口，系统自动缩小下一动作。
- 恢复的目标是重新进入项目，不是追赶失去的产出。

## 6. 核心体验

### 6.1 十日周期建立

1. 用户通过手动输入、系统分享、快捷指令、浏览器、日历或已授权项目工具收集任务。
2. AI 去重、聚类并追问唯一 Definition of Done。
3. AI 提议一个十日目标、最多三个可验证结果和第一天的最小动作。
4. 用户确认或修改后激活周期；其他输入进入停车场。
5. 硬件十枚日珠全部弹起，第一枚显示绿色。

### 6.2 每日执行

1. 用户旋转中央轴，以磁性棘轮和短震动确认“回来”。
2. App 仅显示今天一个动作和必要上下文。
3. 完成后用户按下当前绿色日珠。
4. 日珠下沉并锁定；下一枚日珠变绿。
5. App 记录完成时间和用户可选的一句话结果，不自动追加任务。

### 6.3 22:00 Seal

1. 到用户设定的停止时间，戒断 App 停止新建会话和继续生成。
2. Tenfold 震动一次，绿色日珠熄灭。
3. AI 把未完上下文压缩为明天的一张恢复卡。
4. 用户若强制继续，必须长按中央轴，并回答“明天要牺牲什么”。
5. Override 只记录原因，不羞辱或公开。

### 6.4 24 小时恢复

1. 漏掉一天后，系统保留当前周期，不清零。
2. 用户双击中央轴进入恢复状态。
3. AI 将下一动作缩小到 5–12 分钟可执行范围。
4. 在 24 小时内完成即可继续原周期；未完成则提示重定目标或结束周期。

### 6.5 周期结束

- 十枚日珠全部下沉后，只提供完成、延长一次或结束三个选项。
- 复盘只问：完成了什么、停止了什么、下一轮还值得继续吗。
- 新周期通过按住中央轴并逆时针旋转复位；具体机构由结构验证决定。

## 7. 硬件需求

| ID | 需求 | 验收标准 |
|---|---|---|
| HW-001 | 十边形金属 EDC，目标 46 × 46 × 14 mm | EVT 不超过 48 × 48 × 15.5 mm |
| HW-002 | 十枚等距日珠，正面完整可数 | 用户正视与手持均能准确数出 10 枚 |
| HW-003 | 日珠按下后锁定并下沉 1.2–1.5 mm | 盲摸可识别，不会自行弹起 |
| HW-004 | 当前日珠可在十个位置呈绿色 | 室内清楚，暗处不刺眼，关闭后无明显电子灯带感 |
| HW-005 | 中央轴支持旋转、按压与触觉反馈 | 单手完成；事件识别成功率 ≥95% |
| HW-006 | 支持 BLE，同步失败时本地记录 | 断网完成状态不丢失，重连后幂等同步 |
| HW-007 | 支持 NFC 近场唤起 / 配对辅助 | NFC 不可用时不影响核心循环 |
| HW-008 | 无屏、无常开麦、无生理传感 | 拆机 BOM 与固件权限均符合 |
| HW-009 | 目标续航 7–14 天 | EVT 正常使用 ≥7 天；DVT 目标 ≥10 天 |
| HW-010 | 隐藏充电触点与桌面底座 | 触点不破坏正面；错误方向不能充电或短路 |
| HW-011 | 防误触 | 口袋模拟 8 小时误完成率 <1% / 日 |
| HW-012 | 基础耐久 | 日珠 10,000 次、中央轴 50,000 次后功能正常 |

IP 等级不在首轮承诺中。结构冻结后再根据缝隙、轴承和充电方式确定目标。

| FW-002 | 所有事件使用单调递增序号，App 重试不得产生重复完成 |

| FW-006 | 错误状态只用有限灯光 / 触觉编码，不在硬件上展示文本 |

## 9. App 需求

| ID | 需求 |
|---|---|
| APP-001 | Inbox 支持手动、系统分享、快捷指令、浏览器和日历输入 |
| APP-002 | 首轮只允许一个激活周期；其他项目进入停车场 |
| APP-003 | 编辑并确认 Definition of Done、三个结果和今日动作 |
| APP-004 | 显示十日状态、今日动作、Seal 时间和恢复卡，不制造信息流 |

| APP-008 | 蓝牙、通知、日历等权限按使用场景逐项请求 |
| APP-009 | 无账号或网络时仍能运行本地十日循环 |

## 10. Attention AI 需求

### 10.1 必需能力

1. 去重：识别同一任务的多个表述，不重复生成项目。
2. 聚类：按项目 / 结果归并，不按来源工具分裂。
3. 澄清：缺少完成定义时只追问一个高信息量问题。
4. 收敛：输出严格遵守 1 / 3 / 1 上限。
5. 估时：将今天动作压缩到 5–45 分钟，恢复动作压缩到 5–12 分钟。
6. 封存：在停止时间把上下文压成明日恢复卡。
7. 解释：说明为什么某任务被停车、合并或拒绝进入当前周期。

### 10.2 禁止行为

- 未经用户确认直接激活或删除项目。
- 为提高互动自动生成更多建议、子任务或提醒。
- 根据任务内容推断心理疾病、人格或工作能力。
- 在用户拒绝云处理后上传原始任务文本。
- 将模型输出描述为医学、法律或财务专业意见。

### 10.3 确定性兜底

模型不可用时，App 仍使用固定规则：

```text
选择一个项目 → 写一句完成定义 → 最多列三个结果
→ 选择最小的未完成结果 → 写一个 12 分钟动作
→ 到 Seal 时间保存上下文并停止
```

## 11. 状态机

| 状态 | 进入条件 | 允许动作 | 退出条件 |
|---|---|---|---|
| Unpaired | 新设备 / 恢复出厂 | NFC / BLE 配对 | 绑定成功 |
| Ready | 已绑定、无激活周期 | 查看电量、开始周期 | 周期确认 |
| Active | 周期进行中 | 旋转回来、按珠完成、同步 | 当天完成 / Seal / Grace |
| DayDone | 当天日珠已下沉 | 查看状态、等待下一天 | 本地日期切换或用户开始下一天 |
| Sealed | 到停止时间或手动长按 | 查看恢复卡、授权 Override | 次日 / Override |
| Grace | 漏日后 24 小时恢复 | 完成缩小动作 | 恢复成功 / 超时 |
| CycleDone | 十枚日珠下沉 | 复盘、结束、复位 | 新周期或归档 |
| Error | 传感、存储或同步异常 | 重试、离线继续、诊断 | 恢复 / 售后 |

## 12. 数据与隐私

- 设备只保存周期状态、事件序号和必要诊断，不保存完整任务文本。
- 任务文本默认本地优先；调用云模型前明确展示数据范围。
- 连接器逐个授权，撤销后停止同步并提供已导入数据处理选项。
- 不采集音频、位置轨迹、生理信号、联系人或与核心功能无关的设备数据。
- 支持账户数据导出、删除和本地设备解绑。
- 若调用境外模型，立项前完成数据流图、PIPL 影响评估和数据出境路径判断。

## 14. 成功指标

### 问题与行为门

- ≥60% 测试用户完成首个十日周期。
- ≥70% 设定停机日按时进入 Seal，Override 必须有原因。
- ≥50% 第 21 天仍主动携带 / 摆放并触发物件。
- 物件组第二轮重启率比纯 App 组高 ≥15 个百分点。

### 硬件门

- 正常使用续航 ≥7 天。
- 交互识别与同步成功率 ≥95%。
- 普通用户无需指导即可配对、完成、封存和恢复。
- 达到 HW-011 / HW-012 的误触与寿命目标。

### 付费门

- 出现可退订金、预订单或等价真实金钱信号。
- “很酷”“我会买”不计入支付证据。

这些阈值是产品决策门，不是行业基准。30–40 人实验只提供方向性证据。

## 15. Kill Criteria

出现任一情况，应停止或退回更轻方案：

1. 用户只有外观兴趣，没有近期真实的项目失控问题。
2. 新奇期后，物件在携带、回来或按时停止上不优于纯 App。
3. AI 持续增加任务、提醒和分支，无法稳定遵守 1 / 3 / 1。
4. Seal 和恢复机制制造羞耻、焦虑或更强的强迫使用。
5. 十珠结构无法同时满足误触、寿命、噪音、厚度和成本。
6. 规模 COGS、退货和售后无法支撑验证出的价格。

## 16. 阶段计划

| 阶段 | 时间假设 | 目标 | 通过条件 |
|---|---:|---|---|
| P0 软件循环 | 10 天 | 验证任务压缩和 22:00 Seal | 用户能完成循环且减少分叉 |
| P1 外观 / 机械 | 2–3 周 | 验证携带、把玩、十珠与复位 | 外观、盲操、误触、噪音方向通过 |
| EVT | 6–8 周 | 10–20 台电子样机 | 续航、同步、耐久和结构堆叠通过 |
| DVT | 待 EVT 后报价 | 设计验证、认证预检、供应链 | 关键规格冻结、风险闭环 |
| PVT | 待 DVT 后报价 | 小批生产与质量系统 | 良率、治具、包装和追溯通过 |

时间是假设，不是供应商承诺。

## 17. 当前开放决策

- 十珠采用独立锁定柱还是统一凸轮轨道。
- 中央旋转检测采用磁性索引、编码器还是纯机械把玩 + 独立按键。
- 铝标准版与钛高配版是否同时进入 DVT。
- 首发 App 是独立应用、现有戒断 App 模块，还是两者共享核心服务。
- 中国首发、海外众筹或设计社区小批发售的顺序。
- AI 推理采用本地、小模型云服务或可切换供应商。
