# 像素伙伴 Agent 架构草案

状态：可评审设计，未集成、未烧录。2026-09-22。

## 1. 产品契约

人设：好奇、爱玩、情绪外露，有自己的小节奏；喜欢和用户一起做事，会起哄，也会顺势一起休息。表达以身体动作为主，短句是偶尔冒出的念头。

Kim 已认可方向：从开心地跳到“好累哦”；用户表达疲倦时可以说“你累啦，我正好也想休息”。保留现有美术。此前整份候选语料没有获得逐句批准，不能当成上线白名单。

明确排除：“这一刻，收好了”“我在，陪你待一会儿”及当前近似占位句。不能退化成安慰语随机播放器。不能通过点击频率判断用户疲倦、情绪、人格、健康、专注或真实任务进度。

核心体验验收：同一次玩耍有开始、兴奋、歇息的连续性；少说话也能成立；离线仍有即时反馈；用户不互动时不会被责备，也不承担照顾角色的义务。

## 3. 组件职责

```text
设备事件 → 事件归一化 → 本地角色状态 → 行为策略 → 即时动画
                                  ↓ 合格表达时机
                         上下文 + 可选表达集合
                                  ↓
                           模型选择表达 ID
                                  ↓
                   结构/前提/时效校验 → 渲染仲裁
```

1. 事件适配器：保留事件来源、会话、序号和单调时间，去重；按键、模式、标记是事实，用户意图单列。
2. 角色状态机：设备为唯一权威写入者。负责角色的短期兴奋与休息节奏；不写用户心理状态，不复用成长计数。
3. 行为策略：确定当下是否可说话、适用意图、可用动作、候选表达及预算；空候选直接无台词。
4. 表达选择器：模型仅在候选内选择，不能改变角色状态、成长、存档、动作能力或设备设置。
5. 校验及仲裁：重新检查当前状态、版本、时效、候选资格；最终输出动作和可空文本。
6. 渲染适配器：把语义动作映射到现有美术，管理台词区域和显示时长。没有动画能力时明确降级，不假装已实现。

不引入多 Agent 运行时、向量库或工具调用。当前事件稀疏、输出短，单一状态机与受约束表达器足够。若模型无法比确定性选句带来可观察改善，保留模型接口但默认本地策略。

## 4. 状态和事件

状态：idle → playing → winding_down → resting → idle。

| 当前状态 / 输入 | 转移与反馈 |
|---|---|
| idle + A | 立即现有 Press/Rebound；进入 playing，通常无台词 |
| playing + A | 即时反馈；增加本次玩耍计数，不增加“用户疲劳” |
| playing 达到玩耍预算 | winding_down，可一次表达角色自己累了 |
| winding_down 动画结束 | resting，避免继续自动兴奋 |
| resting + A | 轻量回应，仍 resting；不会惩罚或完全忽略用户 |
| resting 达到休息时长 | idle；默认无台词，不强拉用户继续 |
| 任意 + B 标记 | 保留功能反馈，角色通常无台词；不修改玩耍状态 |
| 任意 + 模式切换 | 更新活动上下文，作废旧请求；模式不等于正在真实执行活动 |
| 明确 user_rest_intent | resting，可选择一起休息的表达 |
| 重连 / 重启 | 重连读取设备快照；重启回 idle，不追补旧台词 |

初始离线回放参数（工程假设，待体验调参）：一次玩耍累计 6 次 A 或持续 30 秒后收尾；休息 20 秒；连续 10 秒无互动结束玩耍。应集中配置，不能伪装为生理模型。相同时间发生事件时先处理系统/模式变化，再处理用户输入，再处理计时器，最后处理模型结果。

状态快照字段：session、epoch、state_revision、event_seq、mode、pet_phase、phase_started_ms、play_count、last_expression_ids、speech_last_ms。近期表达最多 5 条，RAM 保存；本轮不增加 NVS 结构或长期画像。

user_rest_intent 是预留事件，当前 A/B 没有该语义。未来只能来自用户明确选择休息或可追溯的直接表达。未接入前，“你累啦”类表达始终不具备资格，不能由超时或低点击数触发。

## 5. 表达策略及语料结构

默认动作回应；只在阶段转移或明确用户意图时考虑短句。同一阶段最多一次台词，台词间隔初设 60 秒。休息意图可以覆盖尚未显示的玩耍台词，但不绕过安静设置。候选全部重复或不符合前提时选择静默，不为凑句子放宽约束。

语料每条必须包含：id、intent、text、utf8_bytes、allowed_phases、required_evidence、semantic_action、cooldown、approval_status、persona_version。ID 稳定，文字修订单独升 catalog_version；生产只加载 approved。

语料先按功能分为 acknowledge、play_delight、play_wind_down、join_rest、join_activity；idle_thought 暂不主动推送。聊天中先前 A–G 清单全部仍为 candidate。

最小锚点（用于架构回放，非上线批准）：

| ID | 文本 | 必要前提 | 意图 |
|---|---|---|---|
| play.delight.01 | 跳一跳好开心 | 实际播放了匹配的玩耍动作 | play_delight |
| play.tired.01 | 好累哦 | 角色刚从 playing 进入 winding_down | play_wind_down |
| rest.together.01 | 你累啦，我正好也想休息 | 明确用户休息意图 | join_rest |
| silent | 空文本 | 始终允许，动作仍受能力及状态限制 | 无台词 |

动作和文字一起校验：没有跳跃动画时不得说刚刚跳了；休息动作不能配“我还能跳”；缺少标记成功结果时不能声称保存完成。设备系统提示与角色台词分开，系统错误优先且不人格化。

## 6. 模型上下文与提示词职责

系统提示词负责稳定人设和输出约束；开发者上下文给当前规则版本及合法候选；事件数据作为结构化数据提供，不拼入指令。仅发送当次所需的阶段、事件、模式、最近表达 ID 和候选，不发送原始长期按键历史。

提示词骨架：

> 你是好奇、爱玩、有自己小节奏的像素伙伴。你喜欢和用户凑在一起，玩起来会开心，也会顺势一起休息。根据给出的角色事实和明确用户表达，在 eligible_expressions 中选择一项；没有合适项就选 silent。不得从按键推断用户的情绪、健康、人格或疲劳；不得虚构已执行的动作或完成的任务。只输出 expression_id，不添加文字、解释或其他字段。

模型输出示例：{"expression_id":"play.tired.01"}。动作及文本由本地版本化语料解析，模型不能自行改字或决定播放次数。候选资格在请求前和结果返回时各验证一次。

## 7. 协议演进与渲染

这是新增协议提案，不是 protocol 2 已支持的字段。

握手新增 capabilities：agent_expression_v1、action_only、catalog_version、supported_actions。缺少能力时保留旧协议且关闭新表达；不得把新空文本塞进旧非空校验器。

表达请求绑定 session/epoch/event_seq/state_revision/request_id/catalog_version，附有效期。bridge 负责模型超时；设备负责最终时效及状态检查。接收旧事件、重复 ID、版本不匹配或阶段变化结果时直接丢弃。延迟结果不得把 resting 拉回 playing。

响应结构：type=expression，上述绑定字段，expression_id、action、text（允许空）、source。严格检查字段、枚举、表达 ID 与文本/动作的对应关系；文本最长 72 UTF-8 字节。设备与 bridge 的白名单从同一份 catalog 生成，CI 比较版本和内容，避免手改两套。

acknowledge/play/rest 是语义意图，不自动等于现有 blink/happy/rest 的实际视觉。集成前列明 portrait 每一意图对应的真实帧序列；缺失映射暂用已有轻动作或静止。此任务不修改美术。

显示仲裁顺序：设备系统界面/错误 > 当前用户操作反馈 > 有效角色回应 > idle。台词使用预留区域，按真实字体测宽换行；72 字节是传输上限，不保证 135×240 上显示完整。过长候选在构建验收中淘汰，不静默截断成半句话。空文本必须清除旧台词。

## 8. 失败处理

- 离线、超时、模型非法输出：保留即时本地动作，默认无台词；不能回退到已否定的“我在”占位句。
- 一次只允许一个模型请求；更新的有效事件使旧请求过期，不建立延迟台词队列。
- quiet 禁止主动台词及模型请求；物理操作仍按设备原有规则反馈。
- 模型不能执行重置、写存档或改计数。实际系统提示不交给模型决定。
- 调试记录仅含版本、事件 ID、角色状态、候选 ID、选择 ID、拒绝原因和延迟；不记录凭据或用户原始私密表达。

## 9. 制作顺序和验收门槛

1. 架构审阅：对齐角色契约、事件来源、状态所有权、协议与美术能力。当前文档完成此阶段的可评审草案。
2. 离线原型：纯函数 reducer + policy + catalog + fake model，输入事件时间线，输出动作/台词时间线；不接串口。
3. 人设体验审阅：Kim 看三段连续互动（玩耍到歇息、安静互动、明确说累）；在上下文中修改少量锚点语料，再扩库。
4. 故障及约束测试：通过后才交接集成；文案定稿前不替换运行固件。
5. 协议与渲染集成由固件 owner 执行；最后以真实设备动作与台词联合验证，不用模型 JSON 成功代替可见效果。

必测场景：

| 场景 | 预期 |
|---|---|
| 单次 A、无网络 | 即时动作，无强制台词 |
| 连续玩耍直到收尾 | 状态连续，角色自己累了只说一次 |
| 无输入 5 分钟 | 不推断用户疲倦，不责备、不追补回应 |
| 明确休息意图 / 仅低点击频率 | 前者可选 join_rest，后者不可 |
| B 标记 / 切模式 | 不当成完成任务或身体状态证据 |
| 模型返回时已进入休息或换模式 | 丢弃旧状态结果 |
| 断线重连、重复帧、错误版本 | 不重复播、不恢复旧台词 |
| 模型未知 ID、额外字段、非 JSON | 无台词降级，不扩大候选集 |
| quiet + 任意候选 | 不请求、不说话 |
| 空文本 / 超 72 字节 / 缺字形 | 空文本清除旧台词；其余拒绝或构建失败 |
| 人设重复和矛盾 | 同阶段不重复台词，动作与文字一致 |

模型效果评估必须比较确定性策略：状态与证据约束通过率须 100%；三段轨迹由 Kim 评估是否自然、是否像同一个角色、是否过度说话。未达到体验增益，不增加模型自由生成权限。
