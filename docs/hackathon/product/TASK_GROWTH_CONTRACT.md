# 阅读宠物：任务成长与照料最小实现契约

2026-09-22 · 产品裁决，供当前协调owner派既有软件执行。替代100次点击成长。当前是待实现契约，不是设备已完成声明。

## 1. 首轮闭环与范围

主机本地入口创建一个任务节点 → 用户主动确认“此节点已完成” → 主机先持久化确认记录 → USB发送 → 设备原子保存完成ID与累计数 → ACK → 达到门槛进二阶 → 设备解锁最近标记回看。节点例子可为“读完这一节并写一句理解”，不将点击、时间或Agent推测作为完成。

首版由主机CLI完成创建/展示/明确确认/重试；不承诺已有App接入。确认必须显示任务标题与节点内容，支持取消；不可在启动、定时器、串口重连时自行制造确认。Agent不能调用完成接口。断线可在主机排队，只有设备ACK后才显示“已同步”，未ACK显示待同步。

二阶先实现设备本地最近标记回看，使用已有16条环形记录；不是动画或模式标签。“本书”关联当前不存在，因此界面称“最近标记”，不可伪称本书页码。基于已确认节点的下一步建议后置，待真实任务上下文/Agent入口/屏幕接入另行验收。

## 2. USB协议与持久化

沿用NDJSON与协议2；新增命令显式version=1。单帧不超过现有512字节输入限制。task_id/node_id均为1–40字节ASCII安全标识，允许字母、数字、下划线、短横线；node_id主机生成且全局唯一。设备不接收原始论文、私密正文或任意执行代码。

```json
{"type":"node_complete","protocol":2,"version":1,"task_id":"read-001","node_id":"node-001","confirmed":true}
```

设备成功回复：
```json
{"type":"node_ack","protocol":2,"node_id":"node-001","status":"applied","completed_nodes":1,"growth_stage":"young"}
```

同一node_id同一task_id重发返回status=duplicate及当前累计数，不增加成长；同node_id不同task_id返回conflict。非法字段/类型、confirmed不是严格true、超长ID均reject。保存失败返回storage_error，不发applied。ACK只是设备收到并保存用户确认，不证明客观阅读效果。

设备schema2包含：已提交节点ID及task_id、completed_nodes、growth_goal、照料状态、原互动统计/模式/会话/16标记。首版最多64个去重记录，不淘汰旧ID；满后新ID返回capacity_full，旧ID仍可幂等重试，严禁静默挤掉旧ID又重复计数。主机完整账本保留确认时间与节点文本，设备只保存必要标识。设备计数与去重表在同一状态包原子提交，读回核对；存储失败锁止后保持最后有效已提交状态，重启恢复。

新增growth_query只读返回schema、completed_nodes、growth_goal、growth_stage、去重容量剩余、storage_ok；既有hello加这几个字段即可，不混用interactions_lifetime。未收到ACK可按原node_id重试，不换ID。所有串口操作由单一主机进程/租约串行执行。

## 3. 迁移与成长门槛

读取schema1后保留interactions、session、mode及markers；completed_nodes置0、去重表为空、stage回young。旧lifetime只保留为历史互动，不能迁移成任务完成，旧100点击成年也不继承为已完成任务。界面/交付说明明确“成长改按任务节点计算”。

用新NVS键保存schema2，验证成功才使用；保留旧schema1键供回退。不得因schema不符覆盖唯一旧数据；损坏则报告失败、停止计分，不擅自清空/erase NVS。双槽或等效可恢复提交：断电后选择最新完整有效记录，不能出现计数更新而去重未更新。

成长门槛为固件命名配置DEFAULT_GROWTH_GOAL，首次创建schema2时固化到存档；产品首版演示值3个确认节点。构建/文档显著标“演示门槛3”，不是论文结果；更新固件不能悄悄改变已有宠物门槛。不开放普通串口随意改门槛接口。本次不增加死亡、自动退阶或照料缺席惩罚。

## 4. 两键交互与照料

保持B短按松开（<700ms）标记、B长按松开（≥700ms）切模式，长按不先产生标记，电源键不碰。

主页A按下先给即时压扁动画；松开<700ms执行一次照料，有便便先清理，没有则喂饭。照料只改care状态，不改completed_nodes、stage或节点账本。演示循环：每次喂饭增加一格饱食，最多3格；第3次形成1个待清理标识，下一次短按清理并把饱食归0。明确为简化玩法参数，不模拟生理规律；不按现实时间生成惩罚。按住不连发喂饭，连续独立按压可连续玩。照料存档批量写，UI不逐击弹长文。

A长按松开≥700ms：二阶进入最近标记回看，不执行喂饭/清理；一阶只短提示“完成任务后解锁回看”，不造假记录。长按期间仍可本地按压动画。

回看页显示当前第几条/共几条、会话号、会话相对时间及当时模式，不显示虚构页码。A短按下一条循环，B任意按压松开退出并消费该次输入，不能额外写标记/切模式；10秒无操作回主页。无记录显示“还没有标记”。已有reading_query只读查询保持可用，二阶解锁的是设备直接浏览入口，不能声称底层数据此前不存在。

## 5. 验收清单

1. 连按100/1000次、长按、等待、切模式均不能使completed_nodes增加；喂饭/清理状态真实可见。
2. 主机取消确认不发送；明确确认一个新节点仅增加1；没有App时按真实CLI入口演示，不伪装自动识别阅读。
3. 同节点重发、ACK丢失后重试、串口重连及重启后重试均不重复；ID冲突/容量满/畸形包无成长。
4. 第3个确认节点按演示配置进二阶；首次/重复ACK与设备屏幕状态一致；照料不影响门槛。
5. 在写前、写中、ACK前断开/重启，恢复后节点与计数一致；保存失败不报成功，不丢旧有效状态。
6. 用含非零互动和标记的schema1迁移，保留历史数据但完成数0；迁移重启不反复清零schema2；旧版键仍可恢复。
7. 二阶真实长A进入最近标记、A翻页/B退出，无附带照料/误标记/误换模式；空记录、16条环绕均有明确结果。
8. B699/700ms边界与A短长互斥、两键同时输入、millis回绕做状态机测试；实际按键和屏幕另验，不能用协议注入冒充手按。
9. 无主机/网络仍能照料、保存本地标记和已解锁回看。未同步节点明确待同步，不先成长。
10. 原有间歇USB静默须独立收口；以上协议测试不能用一次重启后成功代替多次重开可靠性。
