# 十日环｜黑客松产品需求 v0.1

日期：2026-09-22。状态：可执行候选规格；不是实现完成报告。范围只替代本轮黑客松的旧规格冲突项，不覆盖旧 PRD。

## 产品判断

为正在多个 AI 会话间反复分叉、临近收工却仍想“再改一点”的项目推进者，把混乱输入收敛成今天一个可完成动作，并把完成、停下和次日回来交给一个可把玩的实体物件。

**现有三套附件不足以证明硬件产品价值。** 把玩具绑上显示器不会自动产生价值；快捷键完全能够记录完成和封存。硬件值得继续的假设是：用户离开工作屏幕后，手里仍有可持续把玩的机械物件，同时能够明确提交、获知并保留自己的承诺，且不必重新进入任务或消息界面。软件能替代逻辑，普通玩具能替代机械触感；只有两者整合减少回屏和错记、且携带负担可接受，才值得做一体硬件。

### 首个场景与可验证增量

示例是演示用虚构任务，不是用户研究：21:50，用户已有 landing、固件、路演三个分叉，十分钟内想结束工作。输入“明天展示一个真实闭环；今晚只剩12分钟；别再改配色”。AI建议“验证一次设备确认，留下失败记录”，用户接受。之后把玩不改进度；真正完成时操作实体确认；未做完也可封存。次日恢复的是昨天留下的下一步，不是又一页待办。

| 替代品 | 已能做好什么 | 本产品必须额外证明什么 |
|---|---|---|
| 键盘宏/鼠标快捷键 | 最快触发完成、封存；成本很低 | 离开键鼠后仍可操作和识别结果，减少回屏，错误不增加 |
| 手机 App | 随身、可显示全文和离线保存 | 取出到操作更少，避免解锁后进入其他内容；不是宣称手机必然使人分心 |
| 普通减压玩具 | 无电机械触感、价格低 | 同一手中明确记录与反馈，比玩具+快捷键组合更少切换 |
| M5单独外置按钮 | 状态、声音、离线事件 | 加机械结构后仍愿意连续把玩和携带；否则不做外壳整合 |

最小改进：真实机械把玩 + 不受把玩影响的明确提交 + 设备本地持久化 + 可区分的成功/失败反馈。无需添加无验证价值的旋转计数。进一步的机械开关接线仅在静止侧触点、走线和误触测试通过后考虑；不能为“联动”让每次减压按压都提交任务。

## 范围和成功门

P0：手动输入；AI或明确标记的规则兜底；用户确认；真实设备接收ack；KEY1/KEY2操作；本地状态持久化；屏幕/可选音码；完成、未完成封存、恢复、下一天；保留真实机械触感。十天是周期上限，Demo不伪造十天留存。

非P0：系统级阻止其他App、全工具连接器、麦克风录音、语音识别、自动读IDE、内球/针阵/旋转检测、主动震动、十珠物理锁存、量产续航、支付与疗效。无屏、金属、原尺寸和十珠可降级；真实机械体验不可删除。屏幕十格只表达数字进度，不是实体日珠。

已知评委问题：为什么硬件、为什么不用键鼠/手机/普通玩具、AI与物件如何闭环。官方评分表、人员、工期未提供。本文其余指标是建议验收维度，不冒充官方标准。

四门单独判定：需求可执行 → 附件几何 → 整机实装 → 现场Demo。用户价值实验单独记录。文档通过不能推导其余门或价值验证通过。

## 需求规则

| ID | 必须实现的规则 | 用户结果 |
|---|---|---|
| R01 | 手动输入1–10条、每条≤500字，带id/text；另填可用分钟5–45、目标期限、当前本地日期/时区、可选停止时间；不自动读取其他工具 | 用户知道交给AI哪些内容 |
| R02 | 云调用前展示所发送字段；拒绝则本地表单。AI输出一个目标、1–3结果、一个今日动作及done_when、parked_ids、uncertainties；校验失败一次重试后转表单；不静默删输入 | AI做减法且可被纠正 |
| R03 | 用户确认具体文本和设备短标题后才能激活。缩略≤24个汉字，由用户确认，完整文本留主机；设备可滚动/分页查看，不静默截断完成条件 | 小屏没有替用户改承诺 |
| R04 | 主机发proposal，设备持久化成功才ack；主机在ack前显示待交付，禁止显示已开始。确认超时5秒显示未确认并允许重试同id | 用户知道承诺是否真的到设备 |
| R05 | 同一周期一天至多一次完成；完成后不追加当日任务、不自动增加新动作 | 完成有终点 |
| R06 | 把玩、IMU、普通短按均不得写完成/封存事件；只有[交互协议](USER_JOURNEY.md)明确确认有效 | 把玩不会污染记录 |
| R07 | 状态先持久化再播放成功提示；写失败保留旧状态并显示失败，绝不播放成功音 | 物件反馈可信 |
| R08 | 没完成也能封存；保存已确认动作、最近用户保存的下一步、时间和未完成标记；不能假装知道用户在别的App做了什么 | 停止不等于宣称完成 |
| R09 | 可信时间下离线完成/封存/查看可用；重启恢复持久状态，无可信时间时仅查看/封存，校时后恢复完成；联网不替用户改动作；次日须确认，漏日不清零 | 不靠云才能收尾 |
| R10 | 下一天恢复默认复用未完成动作；AI缩小动作须回主机确认后另版本交付；设备只确认已有内容 | 恢复不生成未经确认的计划 |
| R11 | 每条事件有device_id/seq/command_id/cycle_id/day_index/revision/type；重发幂等；冲突保持本地已确认事实并提示回主机裁决 | 网络重试不会多完成一天 |
| R12 | 合法获得机械原件、实装全行程、10分钟把玩、单手操作、保持力和接口可达均通过才标一体样机 | 实物而非渲染承诺 |
| R13 | 麦克风默认不启用；仅上传用户确认字段；演示日志只用虚构样例，凭证不进固件/公开仓库 | 演示不泄露真实工作内容 |
| R14 | Demo模式时间跳转常驻标记；AI预录、规则兜底、模拟设备都显式标记 | 评委能区分真实和演示 |

## 工程路线、BOM与关键接口

官方[StickS3规格](https://docs.m5stack.com/en/core/StickS3)（2026-09-22核对）：整机48×24×15mm，屏幕、KEY1/KEY2、IMU、麦克风/扬声器和无线能力可用作工程起点。Reset为电源/复位控制，不作业务键。无内置震动；官方接口能力不等于本项目已经跑通。声音电池模式按官方建议低于75%音量起测，机壳不开拆。

建议最短路线：主机本地表单/AI适配器 → USB串口命令 → M5状态机与本地journal。Wi-Fi是拔线无线Demo的下一门；BLE不与USB双轨同时承诺。USB拔线后已交付动作仍能在电池运行。协议先明确，再由工程冻结具体框架和端口。正式固件与主机实现不在本目录，当前均待工程交付。

协议建议v1：换行JSON，最大4KB；`hello {protocol,device_id,last_seq}`；`offer {command_id,cycle_id,revision,day_index,cycle_start_date,local_date,tz,action_short,done_when_short,stop_at,next_step_short}`；`ack {command_id,revision,persisted:true,state,last_seq}`；`event {...R11,status,pending_sync}`；`event_ack {device_id,seq}`；`query {command_id}`返回`status {command_id,cycle_id,revision,state,last_seq,persisted}`；`set_time {command_id,utc_epoch,tz,source:host_confirmed}`需主机显示时间并由用户确认，设备记录校时与单调计时锚点，重启不能恢复可信时间时标记time_untrusted。拒绝超长、缺字段、旧revision、跨周期覆盖和未知type；错误返回code且不改变状态。只有可信已配对主机可写，USB开发模式须显式进入，不能称已实现生产级认证。AI密钥只在主机环境，设备不保存原始inbox或云凭证。

设备是已激活周期状态的权威，主机是计划文本的权威；一台主机一台设备，避免双写。新计划不得覆盖未回传事件。离线事件队列满时阻止新写并显示需同步；保存失败/校验失败进入只读，不丢旧事实。时钟失效或日期倒退进入时间待确认，仍可封存，不能自动推进天数。系统停止时间只触发“该收工”提示，不自动宣布工作完成或关闭外部App。

| BOM | 数量 | 依赖/状态 |
|---|---:|---|
| M5StickS3原壳整机、USB数据线 | 各1 | 实机在场与可烧录待确认；不承诺采购价格 |
| 合法机械原件 | 1 | 2710405优先仅条件候选；尺寸和静止底座先验 |
| 独立原创托架/紧固件/软垫 | 1套 | 按所选模型README，先公差小样后全套；不能混用螺钉长度 |
| 主机与本地桥、模型调用 | 各1 | 云可失败；表单为兜底；网络非设备本地动作依赖 |
| 外置触觉马达/驱动、Hall/编码器 | 0（P0） | 后续另立电气、载荷和功耗验证，不纳入Demo口述 |

时间人员未知，按资源分档而非承诺工期：A档“单开发者+现成M5，无打印窗口”只做真实电子闭环与独立机械体验，不报一体EDC；B档“软硬各有人+可合法取得原件+至少两轮打印装配窗口”争取一体样机；C档“额外传感器/驱动与调试资源”才探索机械检测或主动触觉。任何档位缺实机证据都只能标模拟。优先次序为本地可靠性→输入交付→AI→实装→无线，而非先接语音。

## 硬件价值对照试验（待执行）

招募至少8名近期有AI项目分叉经历的成人志愿者，记录是否已有玩具习惯。每人使用同一确认后的任务，依次测试A键鼠快捷键、B普通玩具+快捷键、C一体物件、D普通玩具+独立M5（同固件与反馈），顺序轮换；软件内容、提示和停止规则保持一致。E组使用手机App（同内容、确认和反馈规则）复测能否靠现有随身设备替代，不用人为关闭它的离线能力制造优势。

场景1桌前封存；场景2用户自愿离开工作桌3米收尾；场景3次日恢复的压缩演练（明确不是次日留存）。记录真实完成耗时、换物次数、回电脑次数、回看工作屏幕次数、错误/重复提交、结果辨认、额外动作、拿持疲劳、偏好原因。视频和日志经参与者同意；无同意则观察计数，不录人脸。

执行口径：8人×5组×3场景×2轮=240次任务尝试；每组48次，成功率为无需协助、状态正确且无重复事件的次数/48，≥95%需至少46/48，掉线失败与误操作都计分母。每组同样一次教学，不计教学试次；条件顺序轮换，缺席保留缺失并补足样本前不判通过。每次记录换物与回屏计数；偏好在全部条件结束后收集一次。

预注册方向性门：C相对B中位回屏次数至少少1次，操作成功≥95%，不增加错误提交，至少6/8愿意再次选C且说得出具体原因；同时保留桌前场景劣势。小样本不能证明普适性或医学疗效。C相对D还须中位换物次数至少少1次且不增加错误；若D同样好，保留分体方案，取消一体整合投资。若B已同样好，取消一体整合投资；若C只在离桌有效，收窄定位；若声音扰人、静音又频繁看屏，不能继续宣传完全离屏。至少后续7天自然使用再判断新奇效应；黑客松当日不声称留存。
