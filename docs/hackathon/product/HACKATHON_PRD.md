# 十日环｜黑客松产品需求 v0.2

日期：2026-09-22。状态：可执行候选规格；不是实现完成报告。范围只替代本轮黑客松的旧规格冲突项，不覆盖旧 PRD。

本轮实施判断及来源见[产品裁决](PRODUCT_DECISION.md)：日常主路径为“今天到这里，明天接得上”，不是每天重新输入和拆任务。方向经协调认可推进，尚未经用户实验验证；软件差异见[合流表](SOFTWARE_ALIGNMENT.md)。已有承诺直接今日卡和封存入口，Agent在建立、卡住和收尾时按需介入。

## 产品判断

为正在多个 AI 会话间反复分叉、临近收工却仍想“再改一点”的项目推进者，把混乱输入收敛成今天一个可完成动作，并把完成、停下和次日回来交给一个可把玩的实体物件。

**原创EDC的硬件增量仍需验证，验证不阻塞今晚原创实现。** 把玩具绑上显示器不会自动产生价值；快捷键完全能够记录完成和封存。硬件值得继续的假设是：用户离开工作屏幕后，手里仍有可持续把玩的机械物件，同时能够明确提交、获知并保留自己的承诺，且不必重新进入任务或消息界面。软件能替代逻辑，普通玩具能替代机械触感；只有两者整合减少回屏和错记、且携带负担可接受，才支持继续投入一体硬件。

### 首个场景与可验证增量

示例是演示用虚构任务，不是用户研究：21:50，用户已有 landing、固件、路演三个分叉，十分钟内想结束工作。输入“明天展示一个真实闭环；今晚只剩12分钟；别再改配色”。AI建议“验证一次设备确认，留下失败记录”，用户接受。之后把玩不改进度；真正完成时操作实体确认；未做完也可封存。次日恢复的是昨天留下的下一步，不是又一页待办。

| 替代品 | 已能做好什么 | 本产品必须额外证明什么 |
|---|---|---|
| 键盘宏/鼠标快捷键 | 最快触发完成、封存；成本很低 | 离开键鼠后仍可操作和识别结果，减少回屏，错误不增加 |
| 手机 App | 随身、可显示全文和离线保存 | 取出到操作更少，避免解锁后进入其他内容；不是宣称手机必然使人分心 |
| 普通减压玩具 | 无电机械触感、价格低 | 同一手中明确记录与反馈，比玩具+快捷键组合更少切换 |
| M5单独外置按钮 | 状态、声音、离线事件 | 加机械结构后仍愿意连续把玩和携带；否则不做外壳整合 |

最小改进：真实机械把玩 + 不受把玩影响的明确提交 + 设备本地持久化 + 可区分的成功/失败反馈。无需添加无验证价值的旋转计数。进一步的机械开关接线仅在静止侧触点、走线和误触测试通过后考虑；不能为“联动”让每次减压按压都提交任务。

## 原创完整EDC与开发板内托

最新决策：今晚从0到1完成原创机械EDC设计和可安装软件Demo，明天试打。原玩具下载、尺寸、静止底座、Print Only均不再是实现前置。原三套附件及其测试仅作历史问题参考，不作为新原创机构的通过证据；旧版SHA/尺寸见WORKLOG。三个原创方向由建模任务交付，产品不在未审阅新几何前选出赢家。

首个内托针对保持原壳的M5StickS3标称48×24×15mm；这只是包络起点，不是所有端口坐标已验证。原创EDC必须包含自己的机械把玩件、运动限位、防脱、承力骨架、电子固定和可拆装结构，不能仅画侧舱或只放包络球。打印包交付编辑源、全部原创STL、装配关系、BOM/紧固件长度、打印方向/公差小样与装配步骤；未打印时标待试打。

| 模块 | 今晚必须定义 | 明天实物门 |
|---|---|---|
| 机械主体 | 至少一种可重复按压/拨动/旋转的真实机械动作；载荷不压屏幕/PCB/电池；运动件不会靠重力脱落 | 全行程、单手、10分钟把玩、软垫上翻转保持，无卡涩夹手 |
| M5内托 | 独立可换内托，带公差参数；KEY1/KEY2/Reset、屏幕、USB及所需接线窗口有位置依据，保留工具路径 | 真机放入/拆出，不强塞、不压屏，逐键和USB插拔 |
| 其他开发板 | 参数化接口定义，不声称通用适配已通过 | 每一种板重新测量、生成和验收，不能整体缩放旧STL |

内托参数合同：board_profile_id、body_length/width/height、clearance_xy/z、mount_points、keepout_volumes（屏/按键行程/插头外壳/线缆弯曲/天线）、retention_features、wall_thickness与print_material。所有值标来源为官方图/实测/假设；尺寸范围由各原创模型脚本的断言和极值测试给出，产品不虚构通用兼容范围。未知端口不能用猜孔通过。更换板或增外设涉及电源、引脚、驱动及协议能力映射，换内托不等于软件兼容；仅支持已声明的screen/buttons/audio/transport能力，不存在的能力显示不支持。原型优先开放窗口、可换托和公差试件，不为通用化延期首个M5版本。

## 范围和成功门

P0：手动输入；AI或明确标记的规则兜底；用户确认；真实设备接收ack；KEY1/KEY2操作；本地状态持久化；屏幕/可选音码；完成、未完成封存、恢复、下一天；保留真实机械触感。十天是周期上限，Demo不伪造十天留存。

非P0：系统级阻止其他App、全工具连接器、麦克风录音、语音识别、自动读IDE、内球/针阵/旋转检测、主动震动、十珠物理锁存、量产续航、支付与疗效。无屏、金属、原尺寸和十珠可降级；真实机械体验不可删除。屏幕十格只表达数字进度，不是实体日珠。

已知评委问题：为什么硬件、为什么不用键鼠/手机/普通玩具、AI与物件如何闭环。官方评分表与人员未完整提供；最新目标为今晚原创设计与可安装Demo、明天试打。本文其余指标是建议验收维度，不冒充官方标准。

四门单独判定：需求可执行 → 原创整机数字几何 → 整机实装 → 现场Demo。用户价值实验单独记录。文档通过不能推导其余门或价值验证通过。

## 需求规则

主机在本轮指Android companion APK；如通信需桌面桥，桥只承担传输，不新增第二套计划权威。APK安装包、版本号、最低Android版本、安装步骤、SHA256及构建命令须随软件交付；APK能构建不等于已安装验收。

### 最小Agent与用户反馈闭环

Agent职责仅为理解用户输入、归并冲突、提出一个目标/最多三个结果、拆出今日一个动作和可观察完成条件、解释停车原因，并根据用户明确反馈提出下一次恢复动作。可在后台形成候选步骤，但不把长任务树默认塞给用户，也不自主执行外部任务或发送消息。

用户可接受、编辑、拒绝建议；确认后版本冻结。完成时用户自报“完成”，封存时可填“做到哪/卡在哪/下次第一步”，跳过填写就保存原动作并标默认恢复卡。回顾展示确认计划、实际完成/未完成、封存及用户反馈；Agent只能据这些已提供事实提出修订，不能推断用户在IDE做了什么。新动作仍需确认，不自动追加。R02的云同意、上限校验和规则兜底继续适用。

真实LLM调用显示生成中/失败/已生成，失败后提供明确标为“本地规则”的手动选项；缓存旧输出标“已保存建议”，不伪装新推理。云密钥不打包进APK、设备或公开代码；真实云入口缺失时仍交付APK与本地流程，LLM验收记未通过，不把规则引擎称为真实LLM。

反馈状态最少区分：草稿、待用户确认、已在手机保存、待交付设备、设备本地已保存、设备待同步、同步完成、失败、模拟设备。手机保存不能冒充设备ACK，模拟事件使用独立演示会话，不混入真实设备历史。真实设备离线动作遵循R07/R09；手机离线反馈存在手机队列，恢复连接后核对版本再合并，不能覆盖设备事实。

UI采用极客EDC方向：深色克制界面、清晰状态数字/十日进度、今日动作卡和一个主要操作；连接状态与真实/模拟标签常驻，文字/图标补充颜色，不能只靠红绿辨认。日常主路径为今日卡→今天到这里（未完成也可封存）→次日恢复；首次建立或需要修改时才输入→Agent建议→用户确认，辅助设置收起。大触控目标、键盘弹出和小屏滚动必须在APK/手机视口核对；不以装饰仪表盘或假实时数据代替反馈。

| ID | 必须实现的规则 | 用户结果 |
|---|---|---|
| R01 | 首次填一个十日结果、今日卡点/剩余分钟5–45；可展开粘贴1–10条、每条≤500字；载荷带id/text、日期/时区和可选停止时间；已有承诺直接今日卡，不强制重填 | 用户知道交给AI哪些内容 |

| R03 | 用户确认具体文本和设备短标题后才能激活。缩略≤24个汉字，由用户确认，完整文本留主机；设备可滚动/分页查看，不静默截断完成条件 | 小屏没有替用户改承诺 |

| R13 | 麦克风默认不启用；仅上传用户确认字段；演示日志只用虚构样例，凭证不进固件/公开仓库 | 演示不泄露真实工作内容 |
| R14 | Demo模式时间跳转常驻标记；AI预录、规则兜底、模拟设备都显式标记 | 评委能区分真实和演示 |

| R16 | Agent使用用户反馈提议恢复卡，用户确认后才生效；回顾只呈现实际记录 | 拆解、执行反馈、回顾形成闭环 |
| R17 | 每日保留当时动作/完成条件、完成真假、封存真假、停点与下一步；回顾按1–10日读历史槽，未记录显示无记录；周期结束可归档及开始新周期，新cycle_id不覆盖旧历史 | 第十天有真实回顾与出口，不是永久死页 |

最小日记录：`cycle_id,day_index,local_date,action_at_time,done_when,completed,sealed,stop_note,next_step`。完成、封存和跨日前保存本日快照；同日修改更新本槽但不改前日，事件journal仍保留事实序列。漏日不制造记录。`CycleReview`逐日显示原动作及完成/未完成封存/无记录，停点可展开，不引入复杂统计。入口为“结束本周期”（归档后无激活周期）及“结束并开始新周期”（先归档再设置新周期）；取消新建仍能查看旧回顾。归档和新建都需本地持久化成功才显示成功；新周期不用旧cycle_id。重启后归档可查，不能只保留最新一天。

## 工程路线、BOM与关键接口

官方[StickS3规格](https://docs.m5stack.com/en/core/StickS3)（2026-09-22核对）：整机48×24×15mm，屏幕、KEY1/KEY2、IMU、麦克风/扬声器和无线能力可用作工程起点。Reset为电源/复位控制，不作业务键。无内置震动；官方接口能力不等于本项目已经跑通。声音电池模式按官方建议低于75%音量起测，机壳不开拆。

最短路线由软件任务冻结一种传输：Android本地计划/Agent适配器 → 单一设备通道（或明确桌面桥）→ M5状态机与本地journal。不同时要求BLE、USB与Wi-Fi；未跑通真实传输时使用显式模拟适配器交付APK，并将真实硬件链路标待验证。下列v1是业务语义合同，换行JSON仅适用于串口；HTTP/BLE可改封装，不改变幂等、版本与保存后ACK语义。实际实现与协议差异须随软件记录。

协议建议v1：换行JSON，最大4KB；`hello {protocol,device_id,last_seq}`；`offer {command_id,cycle_id,revision,day_index,cycle_start_date,local_date,tz,action_short,done_when_short,stop_at,next_step_short}`；`ack {command_id,revision,persisted:true,state,last_seq}`；`event {...R11,status,pending_sync}`；`event_ack {device_id,seq}`；`query {command_id}`返回`status {command_id,cycle_id,revision,state,last_seq,persisted}`；`set_time {command_id,utc_epoch,tz,source:host_confirmed}`需主机显示时间并由用户确认，设备记录校时与单调计时锚点，重启不能恢复可信时间时标记time_untrusted。拒绝超长、缺字段、旧revision、跨周期覆盖和未知type；错误返回code且不改变状态。只有可信已配对主机可写，USB开发模式须显式进入，不能称已实现生产级认证。AI密钥只在主机环境，设备不保存原始inbox或云凭证。

设备是已激活周期状态的权威，主机是计划文本的权威；一台主机一台设备，避免双写。新计划不得覆盖未回传事件。离线事件队列满时阻止新写并显示需同步；保存失败/校验失败进入只读，不丢旧事实。时钟失效或日期倒退进入时间待确认，仍可封存，不能自动推进天数。系统停止时间只触发“该收工”提示，不自动宣布工作完成或关闭外部App。

| BOM | 数量 | 依赖/状态 |
|---|---:|---|
| M5StickS3原壳整机、USB数据线 | 各1 | 实机在场与可烧录待确认；不承诺采购价格 |
| 原创机械主体与运动件 | 1套 | 自行定义机构/限位/防脱；不依赖原玩具 |
| M5可换内托/紧固件/软垫 | 1套 | 先公差小样后全套；不能混用螺钉长度 |
| 主机与本地桥、模型调用 | 各1 | 云可失败；表单为兜底；网络非设备本地动作依赖 |
| 外置触觉马达/驱动、Hall/编码器 | 0（P0） | 后续另立电气、载荷和功耗验证，不纳入Demo口述 |

今晚并行完成原创可试打文件与可安装Android Demo；明天用实机和打印件验装。APK可先交付独立软件闭环，设备未连必须显式模拟；这不替代完整硬件交付。优先级为可安装与本地保存→Agent拆解/确认→单一通信路线→真实设备反馈。打印和固件尚无实证时如实标待验证，不等待市场实验才开始实现。

## 硬件价值对照试验（待执行）

招募至少8名近期有AI项目分叉经历的成人志愿者，记录是否已有玩具习惯。每人使用同一确认后的任务，依次测试A键鼠快捷键、B普通玩具+快捷键、C一体物件、D普通玩具+独立M5（同固件与反馈），顺序轮换；软件内容、提示和停止规则保持一致。E组使用手机App（同内容、确认和反馈规则）复测能否靠现有随身设备替代，不用人为关闭它的离线能力制造优势。

场景1桌前封存；场景2用户自愿离开工作桌3米收尾；场景3次日恢复的压缩演练（明确不是次日留存）。记录真实完成耗时、换物次数、回电脑次数、回看工作屏幕次数、错误/重复提交、结果辨认、额外动作、拿持疲劳、偏好原因。视频和日志经参与者同意；无同意则观察计数，不录人脸。

执行口径：8人×5组×3场景×2轮=240次任务尝试；每组48次，成功率为无需协助、状态正确且无重复事件的次数/48，≥95%需至少46/48，掉线失败与误操作都计分母。每组同样一次教学，不计教学试次；条件顺序轮换，缺席保留缺失并补足样本前不判通过。每次记录换物与回屏计数；偏好在全部条件结束后收集一次。

预注册方向性门：C相对B中位回屏次数至少少1次，操作成功≥95%，不增加错误提交，至少6/8愿意再次选C且说得出具体原因；同时保留桌前场景劣势。小样本不能证明普适性或医学疗效。C相对D还须中位换物次数至少少1次且不增加错误；若D同样好，保留分体方案，取消一体整合投资。若B已同样好，取消一体整合投资；若C只在离桌有效，收窄定位；若声音扰人、静音又频繁看屏，不能继续宣传完全离屏。至少后续7天自然使用再判断新奇效应；黑客松当日不声称留存。
