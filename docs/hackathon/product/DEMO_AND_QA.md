# 90秒演示与评委问答

这是一份目标脚本。当前未有本任务实机端到端证据，不能直接宣称已做到。上台前按矩阵逐项标真实/模拟/不可演示；没有真设备ack时不得把网页动画称作硬件闭环。

## 90秒脚本

| 时间 | 我说的话 | 实际动作/证据 |
|---|---|---|
| 0–12秒 | “我的项目还没做完，但今晚该停了。我怕的不是少做一点，是明天又要重新找回现在的思路。” | 已有今日承诺卡，样例标记；从用户痛点开始，不从空表单开始 |
| 12–25秒 | “这十天只承诺一个结果。今天只验证这一件事；这是我确认过的停止边界。” | 展开首次Agent提议与用户确认记录；本地规则/预录/真LLM分别标记 |
| 25–38秒 | “它已经交到设备。手可以一直玩，不会误记成完成。” | 实机ACK和同一标题；原创机械动作，计数不变。未打印则明确演示试打包，硬件体验待验 |
| 38–55秒 | “现在没做完，我仍然可以确认今天到这里。设备先保存，才告诉我已封存。” | 实体确认或明确SIMULATED DEVICE；未完成标记、保存后的声/屏反馈 |
| 55–70秒 | “我只留一句停在哪。Agent可以帮我压成明天第一步，我确认才替换；断网也不会丢这句话。” | APK输入卡点，保存后再提议；断网显示原句保留，不伪造新推理 |
| 70–85秒 | “演示时间前进到明天。我不用重新规划，接回这一小步。” | DEMO TIME独立会话按钮，触发真实状态转换；看恢复卡并确认，昨日完成与否保持正确 |
| 85–90秒 | “我们做的是允许停下、还能接回的物件。它比手机多出的价值，下一步用对照实验验证。” | 今日卡/恢复线索结果，勿展示虚构留存或疗效 |

90秒为目标脚本，需实测计时。优先演完未完成→封存→恢复一条链；完成计数作为补充，不暗中重置周期插第二场景。没真设备就持续标模拟，不称完整硬件闭环。

## 评委问答

**为什么需要硬件？** 目前是待验证的产品假设。它把真实机械把玩、离桌后的明确提交和本地状态放在同一件物品中。若玩具加快捷键一样好，我们不会用“仪式感”替失败辩护。

**为什么不是键盘宏或鼠标快捷键？** 坐在电脑前它们可能更快，我们保留这个对照。候选优势只在离开键鼠、仍想收尾且不再进入工作界面的场景；要用回屏次数和错误提交验证。

**手机App不也随身？** 能，而且是强替代。需要比较取出、解锁、确认的实际步骤和误触，不假定所有人都被手机分心。手机同样好就没有硬件必要性。

**普通玩具不就够了？** 对单纯把玩够了。本产品额外记录确认后的单一承诺并给出保存结果；仍需与玩具+快捷键组合比较，不能只赢一个被削弱的对照。

**AI在哪里，为什么不用普通表单？** AI只用于把多项冲突输入压缩成一个可验证动作并解释停车项。执行与封存是确定性本地状态机。若表单同样省时、候选频繁被改，AI也应降级，不能为有AI而增加对话。

**旋转如何联动？** 当前不检测。旋转/按压原创机械件负责被动触感，KEY1/KEY2明确提交。没有Hall/编码器就不编造转动数据。随机把玩和正式承诺分开是有意设计。

**反馈是不是震动？完全离屏吗？** 当前是屏幕及可选音码，没有内置触觉马达。声音可在不看屏时确认完成/封存，任务全文、编辑及静音状态需要看设备或回主机。不能宣传全流程无屏。

**真的让用户停止工作吗？** 只确认封存、保留恢复入口；当前不拦截其他软件。行为改变是实验目标，不是已经证明的疗效或强制约束。

**为什么选这个模型？** 本轮从0到1原创完整EDC，首个可换内托针对M5StickS3，不依赖原玩具。新机构按机械玩法、完整防脱、装机与试打证据选择；旧附件测试不能替代原创验证。

**成本、续航、上市时间？** 当前BOM以现成板和打印件建立，尚无整机报价/续航数据。今晚目标是原创试打包与可安装APK、明天试打；这不是量产交期承诺。
