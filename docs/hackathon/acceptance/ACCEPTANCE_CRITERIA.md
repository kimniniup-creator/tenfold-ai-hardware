# 黑客松独立验收门

日期：2026-09-22。依据：本轮明确任务范围及评委替代性问题；官方比赛 rubric、截止时间、路演时长尚未知。以下阈值为团队建议，不是比赛规则。旧 PRD 的无屏、十珠、46mm 可降级；真实机械把玩不得删除。

## 判定规则

PASS=指定证据覆盖要求；FAIL=观察到违背；BLOCKED=缺少必要对象/权限/测量；NOT_TESTED=尚未执行。NO-GO 是该门不放行，不等于所有产物无价值。每次评审锁定完整 SHA、文件、执行环境、证据类型；新 SHA 不继承旧版通过，需影响分析和针对复测。作者自测不是独立复现；包络不是实物；渲染不是握持测试。

| 门 | 允许宣称 | 必需证据 | 不能被什么替代 |
|---|---|---|---|
| G1 PRD 可执行 | 可进入实现/验证 | V1–V4、S1–S4、D1需求可判定、owner与失败处理完整 | 无实物不自动否决；愿景或脚本不能代替状态协议 |
| G2 附件几何可用 | 在标明假设下可供试制评估 | 独立重跑网格/实体、装配坐标、尺寸链、BOM、打印方向；未知源接口明确隔离 | 零相交不能证明端口可达、保持力或真实适配 |
| G3 整机可打印装配 | 指定版本可试制完整样机 | 合法原件/测量、完整接口与运动包络、切片检查、全部紧固件尺寸链、装配/握持/防夹与保持方案 | 假定直径/静止底座不能过门；首次试制成功另记 |
| G4 现场 Demo 可演示 | 指定硬件/固件/软件组合可现场演示 | 真实装机端到端、断网/重复/恢复测试、演练记录和明确模拟标签 | 文档、视频剪辑、编译成功、CAD通过不能代替真实链路 |

## 可执行检查

| ID | 必须回答/验证 | 文档通过条件 | 实测或演示通过条件 |
|---|---|---|---|
| V1 硬件存在价值 | 谁在何时离开哪个失控场景，手为何要拿起它 | 场景、替代成本、独有/增量体验、负向判据明确；不可只写仪式感 | 按 V4记录事实；尚未测则只能称假设 |
| V2 替代性 | 键鼠、手机、普通玩具能否完成同一事 | 同软件条件下区分功能等价与体验增量，承认可替代部分 | 不用功能更多/外观偏好冒充结果更好 |
| V3 真实把玩与吸引力 | 断电仍有可重复机械动作；电子加入不破坏它 | 指定按压/拨转、握法、运动/手指空间；观看吸引与体验价值分开 | 建议5位目标用户各10分钟，记录疼痛/卡滞/松脱/噪音、是否自发再拿起；任何危险夹手或脱落不放行该姿态 |
| V4 对照验证 | 整合硬件相对分离方案有何增量 | 键鼠、手机、玩具+快捷键、玩具+独立按钮设备、一体设备；同任务、交叉顺序、记录混杂因素 | 建议≥5人探索性测试，记录换物/开屏/回工位次数、确认耗时、误确认、偏好理由；若无一致增量或更差，停止宣称必要性并退回软件+独立玩具。小样本不证明市场/医疗价值 |
| S1 输入与AI | 输入入口、载荷、收敛、用户确认 | 字段/上限/错误例、确认前不可激活；1目标/≤3结果/1今日动作 | 非法AI输出拒绝或规则兜底；未授权原文本不上云 |
| S2 设备交付与意图 | PC发送不等于设备收到；把玩不等于完成 | 版本/周期/日期/事件ID、ACK含义、过期/乱序/重复、双阶段确认和取消 | 真实按键触发一次持久状态；连续随机把玩不改变进度；断电不丢已确认状态 |
| S3 实体输出 | 输入→系统→设备可感知输出 | 明确屏/声输出；被动机械触感与主动输出分列 | 用户在指定环境认出完成/Seal/错误；静音时明确需看屏。无外置马达不得称震动；无传感器不得称检测原机构 |
| S4 封存恢复 | 完成、Seal、恢复、下一天和错误 | 状态表含转换优先级、时间来源、离线、误触、丢ACK、重启；不把提醒说成强制封锁 | 断网完成→重启→重连不重复；Seal期间不误完成；模拟次日须显式标签 |
| M1 M5实际能力 | 板型、输入、输出、接口可实现 | K150整机48×24×15mm为名义规格；无内置震动，旋转不自动检测；固件API/接线/BOM可追踪 | 屏键USB实机可达；加载指定固件观察结果；不以板卡支持推定软件已实现 |
| M2 制造接口 | 原件/附件/垫/螺钉尺寸链 | 假设与实测区分；合法取得；不分发受限原件 | 按测试报告指定条件独立复验，源尺寸未知时整机BLOCKED |
| D1 演示真实性 | 哪些真做、模拟、后续 | 每步标签、失效备用、owner；90秒仅为暂定脚本 | 建议连续3轮无人工后台改状态；输入、设备ACK、实体操作、屏声输出、日志关联可见；至少一轮断网/重连与恢复 |

## 证据包与解除流程

每条证据含 requirement ID、被审 SHA、硬件/固件版本、命令或操作、预期/实际、时间、操作者、原始记录位置、限制。测试可在本地合法原件上做，公开仓库只存可分发的精简数据与文字，不上传受限文件、密钥或个人内容。

缺陷交给实际owner；修复提交后由测试复测、验收更新对应门。P0=虚假完成/危险体验/核心链路不能成立；P1=目标门的必修阻塞；P2=不影响当前门的优化。缺少实物不阻止G1通过，也不得用G1通过包装G4。
