# 原创试打包与 APK：本轮验收契约

日期：2026-09-22。范围依据：最新要求“从0到1原创完整EDC，明天试打；可装M5StickS3，保留数据口；Agent拆任务、完整软件反馈、极客UI、打包APK”。本文件优先于旧附件验收中对MakerWorld原件尺寸的依赖，**原创件不再等待原玩具尺寸**。旧报告只保留历史，不作为新模型的失败证据。

今晚可交付的是数字制造试打包和经安装验证的软件Demo；打印后配合、手感、耐久及板端运行另设门。不因尚未实打否决试打包，也不以可打印代替已实打成功。仓库的公开性不改变原创与凭据边界。

用户进一步强调：用户链路须由PM与调研独立思考，不能机械照抄协调者提出的流水线。因此下方软件路径是当前候选的检查参考，不锁定信息架构；PM可提供更合理旅程，验收检查意图、Agent责任、可纠正决策、反馈、退出恢复与可观察结果。首打必须选一个可靠方案，不能把三套未排序STL扔给用户自行试错。吸引力结论须具体到动作、触感机制、使用情境与可体验证据；无实物时只评设计依据，不宣称已证实手感。

## 四个独立放行对象

| 门 | 通过后可说 | 必须证据 | 暂不要求 |
|---|---|---|---|
| O1 数字制造试打包 | 该SHA可进入指定工艺首轮试打 | O-M01..06，完整原创机构/源CAD/STL清单/装配/BOM/校准/独立几何与切片检查 | 不要求已经打印；不等待任何原玩具 |
| O2 软件可安装闭环 | 该哈希APK在记录环境可安装运行，完成标明模式的流程 | O-S01..06，构建/签名/安装/启动/真实界面操作/重启数据及错误模式证据 | 无板时可用常驻标识模拟设备；无key可用诚实规则Agent |
| O3 真实硬件数据闭环 | 该软件/固件/板卡组合真连接并收发状态 | 实机传输、ACK语义、实体键→事件→APP反馈、断线/重连/重复、日志关联 | 未在板上执行不得通过；不阻止O1/O2各自交付 |
| O4 实打体验 | 该材料/切片/打印机样件可装可玩且适配 | 实物装配、全行程、屏键USB插拔、保持、握持、打印缺陷记录 | 明日首次试打后再验证；今晚不是此门通过前提 |

PASS/FAIL/BLOCKED/NOT_TESTED含义与旧标准相同。条件通过需列出准确条件，禁止把缺失的必需证据藏进脚注。每个门锁定完整SHA；APK另锁SHA256、包名、versionCode、签名证书摘要和运行环境。不同SHA不得混用测试数据。

## 机械数字制造要求

| ID | 试打放行检查 | 失败/限制的处理 |
|---|---|---|
| O-M01 完整原创机械玩法 | 明确运动件、固定件、操作动作、限位/捕获、回位或循环路径；全部必要部件自有几何且有数量；断电仍能机械把玩 | 单独电子底座/假运动包络不算完整EDC；需弹簧/轴承则给型号尺寸数量，缺件替代不得宣称同手感 |
| O-M02 装配与电子隔离 | 爆炸图、顺序、每个件可沿规定路径装入；紧固与保持、螺母/垫圈/工具空间、按压力不经屏/电池；可更换内托 | 开口能放入与装好不会掉出需分别证明；不能用最终静态无相交代替装配可达 |
| O-M03 几何和运动 | 实际导出STL闭合/单连通/正体积/单位正确；STEP若交付则有效；静态零件、五金、设备包络及全行程/极限避让独立复现 | 名义接触/关节接触明确排除，不把所有相交归零来掩盖接触；参数端点测试不能称连续全域通过 |
| O-M04 M5接口与数据口 | 首个内托明确K150名义48×24×15；USB插头通路、屏/KEY1/KEY2/Reset可达方案及证据，线缆不穿运动副；未知精确接口用充分开放面并说明验证方法 | 不要求虚构实机验证；只留一个无坐标小孔不算数据口；其他板要独立内托参数与核对，不能称任意板通用 |
| O-M05 可切片试打包 | 每件STL/数量、朝向、打印机/喷嘴/材料/层高假设、最薄壁/细节、支撑区、接触间隙、公差校准件、建议先后顺序；实际CLI切片/预览记录与设置 | 用户打印机未知可用明确通用FDM假设；不把某机G-code称通用。若无可用切片器，报告为切片门未验证，不能说已切片通过 |
| O-M06 可交付与明日操作 | 自包含文件清单、源与导出对应、BOM含非打印件、装配图与打印说明、各件文件哈希；优先试打方案明确、其他方案状态真实 | 不把过程渲染/校验代理体当打印件；STL不漏移动件/盖/限位件；不可隐藏外购件依赖 |

“真实机械玩法”在O1指可审查的机构设计与运动证据；“真实减压/舒适度”需O4用户触摸，今晚不得伪称已测。首轮公差不匹配可通过校准件调整，不得以未知收缩否定所有数字设计。

## 软件、Agent与通信要求

| ID | 安装闭环放行检查 | 必测路径/反例 |
|---|---|---|
| O-S01 构建与安装 | 可复现构建、签名APK、包名/minSdk/目标环境、SHA256；模拟器或真机安装启动记录 | 编译成功不等于安装成功；debug签名须如实标注，不称商店正式发行 |
| O-S02 Agent职责 | 用户输入→LLM或本地规则拆分→可编辑目标/结果/今日动作/完成条件→用户确认；1/≤3/1上限 | 拒绝云、缺key、超时/非法输出能完整兜底；规则标签清晰，未确认不激活 |
| O-S03 完整反馈 | 今日执行、完成确认、封存未完成、恢复/次日、回顾/历史都能真实操作；状态持久化 | 连续重复完成不加计数，杀进程重启恢复；空输入/返回取消/无设备不假交付；保存失败不假成功 |
| O-S04 通信真实性 | 至少一种真实BLE/USB传输实现、公开协议与板端实现/构建边界；设备模拟器明确隔离 | 无硬件显示未连接；模拟成功不改成真设备ACK；断线/超时/重复/旧revision有明确结果；日志去敏 |
| O-S05 移动端UI | 极客EDC视觉有一致状态层级、清楚操作和错误；主要流程截图来自运行APK，记录分辨率/字体缩放 | 关键文本/按钮不被键盘/系统栏遮挡，长任务可读，禁用/加载/错误/模拟状态可辨；静态设计图不代替运行截图 |
| O-S06 凭据/产物 | 无硬编码密钥、日志不输出key/私密任务；明示云发送内容，支持用户配置或无key模式；APK与源码对应 | 公共仓库不提交凭据/本地环境/无关数据；真实上传发送由协调负责，本验收不代发 |

O2可在规则Agent+模拟设备下通过“诚实离线完整Demo”，但同时记录真实LLM、板端通信、实机安装的各自状态。若没有任何Android运行环境，仅构建APK不能通过O2安装运行门，仍可交付标明“未安装验证”的构建产物。

## 协作、阻塞与回归

三模型owner负责原创实现，独立测试负责重跑/切片与反例，软件owner负责APP/固件与运行环境，产品负责统一协议/文案，验收负责对照证据判定。硬件操作/模拟器写操作由软件和测试协商单一操作者，避免并发操作同一实例。

P0=错误声称实测、核心数据损坏、危险机构或泄密；P1=阻止相应门的缺件/干涉/安装流程失败；P2=不阻止该门的改善。修复需新SHA/哈希、影响说明、独立复测。无需为已授权可逆修复再向用户确认。缺实物/外部key不阻止独立文档、离线软件和试打包工作。
