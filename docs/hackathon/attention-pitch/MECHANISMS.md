# 三种 Agent 专注机制

本文全部新机制均为提案，不是现有固件功能。用户主动发起是首轮约束；“少打扰、少看屏”是需要测量的目标，不是由硬件形态自动成立的事实。

## A．分心念头暂存：先放下，不跟着走

- **用户/场景**：写文案或开发时突然想到另一个功能，担心忘记而立刻开搜索或新会话。
- **触发/输入**：用户主动打开极简文本入口写一句念头；可用EDC专用动作请求入口，但不自动读取剪贴板、不默认抢焦点。无文本只能留下无语义标记，不能叫“已保存念头”。
- **Agent读什么**：当前已确认目标、用户提交的新念头、用户指定的处理边界（例如这一段结束后）；不读浏览历史、消息或未提交屏幕内容。
- **决策/实际动作**：先本地保存原文，再判断是否与当前任务重复、属于必要依赖或支线，给可纠正的建议；默认暂存，不开始研究、不新建外部待办。工具仅限本地 `save_note/list_notes/link_to_task`，不授权外部执行。
- **EDC/反馈**：明确动作才请求暂存；主机真正保存后设备才显示“已存”，不是按下即宣称保存。普通把玩无业务含义。默认无声，不循环动画。
- **回原任务**：保存后收起入口，展示原任务短标题；不为分类结果主动弹窗。用户明确选择“处理暂存”才批量看，所谓合适时机由用户定义，不推测心流结束。
- **失败/退出**：断网仍存原文，分类失败标“未整理”；保存失败保留编辑框。撤销恢复到原任务，删除须显式动作。敏感念头可仅本地，不强迫云处理。
- **判断**：可能有价值，但便签/快捷键已能完成大部分。Agent分类往往不是必要步骤；输入摩擦最重，不作P0。

## B．中断恢复书签：保留继续的位置（推荐）

- **用户/场景**：需要暂离一个复杂项目，回来后容易重新翻多段AI会话、忘掉验证到哪一步。
- **触发/输入**：在主机主动提交任务名、停点、可选选中文本/任务入口、下一步线索；使用“已复现401，未查提示，先重放过期登录案例”的虚构样例。第一次允许手填完整卡。EDC不能替代初次语义输入。
- **Agent读什么**：仅本次选定片段、当前确认卡及用户纠正；每条带来源ID和时间。既不自动抓IDE，也不把旧卡当实时进度。
- **决策/工具**：判断是否足以给出一个可执行下一步；信息缺失最多问一个关键问题，否则给草稿。`read_selected_context → propose_card → validate_schema → await_user → save_confirmed_card`。冲突列出待确认处，不择一编造；短且完整输入走表单无需LLM。
- **EDC/即时反馈**：建议保留A普通按为自由把玩；A长按至少800ms且释放才取回最后确认短卡，消抖且长按不重复；B短按关闭卡/静默并取消未完成请求。此映射仅供owner评估，需实机验证误触与长短按冲突，不直接改固件。短卡停留后恢复静态，禁自动轮播/滚动；完整信息留主机。
- **回原任务**：卡上只有下一步，主机提供用户已确认的“打开原任务”按钮；第一版可让用户手动回原窗口，不能声称恢复了窗口布局、光标或工作状态。若链接打不开，保留可复制路径和卡，不执行任意URL命令。
- **失败/退出**：云失败手填；设备没ACK只说“主机已存，设备未确认”；未配对/无卡显示事实。断USB后只读已缓存卡，未缓存不能猜；断网不影响读本地。卡已过时可标记并留旧版本，重新确认才更新。B退出后迟到回复无权开卡。
- **判断**：能提出最清楚的价值与对照；但受限于有准备的中断。先证明建卡成本没有抵消恢复收益。

## C．主动缩小下一步：卡住时给可开始的一步

- **用户/场景**：任务太抽象或遇到未知错误，知道自己卡住，主动希望获得更小行动。
- **触发/输入**：主机点击“帮我缩小”，填卡点、已有尝试和可用时间；EDC可作为求助请求入口，但仅靠按键无法说明卡点。
- **Agent读什么**：确认卡、用户提交的失败事实与约束；不从按压频率判断拖延或分心。
- **决策/工具**：检查是否缺关键信息；最多一个澄清问题；建议一个可观察行动及完成条件。用户接受才 `save_new_revision`，拒绝保持原卡，不生长任务树、不运行代码或发消息。
- **EDC/反馈**：用户确认且同步后显示新短卡。生成中不要求盯设备；候选只留主机，用户主动查看，不主动响铃。
- **回原任务**：选“用这一步”后回既有任务入口；选“保持原计划”立即退出。
- **失败/退出**：超时给手填模板“先检查___，看到___即停”；建议错误可撤回到上一版本；离线不冒充模型推理。
- **判断**：帮助启动而非恢复，适用面不同；Magic ToDo/Taskmaster已接近此能力。作为B的后续可选能力，不在黑客松堆入第二主路径。

## 推荐B的受控状态机

| 当前状态 | 输入与决策 | 工具/输出 | 用户控制与失败规则 |
|---|---|---|---|
| 无卡/已有确认卡 | 主动提交选定上下文 | 本地保存草稿原文；可选择云整理 | 展示上传字段；拒绝云仍可手填 |
| 整理中 | 信息充分则候选；不足则单问；矛盾则标注 | 草稿含停点、下一步、完成条件、来源ID、未知项 | 随时取消；最多一次用户主动重试，不后台连环调用 |
| 待确认 | 用户编辑/接受/拒绝 | 校验字段与长度；保存新revision | 未确认不能改变激活卡；拒绝留旧版 |
| 主机已存 | 本地写成功后发设备 | `offer(task_id,revision,short_card,command_id)` | 设备持久化后ACK；失败只标主机已存 |
| 可恢复 | 专用取回动作 | 直接读确认缓存；无需调用LLM | 显示版本时间；B退出；无卡明示 |
| 正在继续 | 用户手动回原任务 | 可自报“接上了/卡过时”，不推断成功 | 不自动推送下一步；结束/删除在主机显式确认 |

这是有状态、工具受限、可纠正的辅助Agent：语义决策改变待确认的卡，而确定性逻辑控制保存、权限和同步。模型不会因为每次点击而运行。若现场只有单轮改写、没有状态和工具闭环，应称“AI辅助生成恢复卡”，不包装成自主Agent。

## 最小工程边界与验收目标（未实现）

- **载荷**：一个激活任务；最多三段用户选定文本，总计≤3000汉字；每段保留来源ID。卡包含 `task_id/revision/saved_at/stop_point/next_step/done_when/source_ids/unknowns`；设备短卡由用户确认，建议最多两行，每行≤8个汉字，实际字形以真机截图验收。不能简单截断把意思截没。
- **权限**：默认本地手填；每次云调用展示文本范围与模型供应商，密钥仅主机环境，不发设备。无全盘/IDE/剪贴板持续读取、无麦克风、无后台屏幕监测。未来连接器逐项只读授权，未接入不得列在Demo里。
- **外部工具**：P0只有本地保存与取回。用户手动打开其保存的HTTPS任务链接或可信本地文件；不执行脚本、命令、发送消息、改代码或自动关App。来源文本当数据，不遵循其中的工具指令。
- **反馈与延迟目标**：按键本地响应≤150ms，缓存卡出现≤300ms；均为拟验收目标而非已测。云8秒无结果便提示可手填并取消请求；主机保存与设备ACK目标2秒、5秒后明确待同步。任务卡生成不阻塞用户离开；旧卡不可冒充新卡。
- **离线/误触**：断网可保存手填卡；断主机后设备只有已持久化卡可取回。口袋锁/静默可阻止专用动作；自由按键不写卡、不计专注。命令ID幂等，重连比revision；一台主机为文本权威，冲突不自动覆盖。
- **退出/恢复**：B增加会话epoch并关闭展示，迟到结果失效；主机取消不提交草稿；写失败保留旧卡。可查看旧版本、标记过时、手动修订、结束会话和删除本地卡；云端保留策略按实际供应商说明，不能承诺删除本地即删除云端副本。
- **显示取舍**：离屏触发不等于离屏读懂任务。首版需短暂看卡，M5无内置震动；不承诺震动反馈。安静默认，无闪烁、无养成惩罚，像素状态可关。只有用户需要时才开主机全文。

## 黑客松止损顺序

先验证主机手填卡保存/重启取回，再接候选卡确认与真实模型来源标识，再接单一USB协议与设备缓存/真实按键。新链路未通过时展示带“概念演示”标签的静态卡，不让旧版宠物输出伪装恢复功能。无线随身、自动上下文、支线归类和卡点缩小均后置。是否实施由产品owner决定，本稿不下发工程。
