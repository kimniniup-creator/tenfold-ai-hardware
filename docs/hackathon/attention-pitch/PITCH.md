# 三分钟中文路演

当前可直接使用的版本：产品提案与原型进度分开讲。正文635个汉字，约三分钟为排练目标，尚未真人计时；建议每分钟约210–240汉字，加翻页与停顿。演示另计80秒，不含在此三分钟内。

## 讲稿

我想从一句大家熟悉的话开始：Attention Is All You Need。

在这里，我借用的是标题。AI越来越会生成内容，我想解决的却是一个很具体的问题：工作被打断以后，人怎么接着往下做？

请想象一个场景。你正在修登录问题，已经复现了错误，还没验证提示。这时需要离开电脑。回来以后，你又翻代码、找会话、回想刚才准备验证什么。真正开始工作之前，先花了一段时间重新找自己。

我想做的，是一张放在手边的任务书签。

离开前，我主动留一句停点，也可以附上自己选择的上下文。Agent把这些内容整理成一张卡：刚才做到哪，回来先做哪一步，看到什么算这一步完成。信息不够就问一个问题，不替我编。卡由我确认。回来时，我用随身物件取回它，照着这一小步接着做。

Agent的价值要落在整理复杂上下文上，硬件的价值要落在取回这件事是否顺手。它们都不是必需的答案。如果一句便签已经足够，就不需要模型；如果快捷键更方便，就保留纯软件。我想通过对照测试证明增量，而不是先要求用户多带一块设备。

我也不会把按得多解释成更分心。把玩可以只是把玩。设备默认安静，用户需要时才取回卡。像素角色可以告诉我保存是否成功，但不会催我照顾它，也不会给我一个看起来精确的专注分数。

研究给了我一个值得尝试的方向：中断前的准备、外部保存意图，可能帮助人处理任务切换。但这些研究没有验证我们的设备，更没有证明EDC一定让人专注。

目前已有像素交互的软件基础和主机侧测试。任务书签仍是拟补的最小闭环，真实设备链路需要单独验收。接下来，我会把它与手填卡、快捷键和普通物件比较，测回来后多久做出第一个有效动作、任务质量有没有下降，以及为了保存这张卡付出了多少额外操作。

我希望最后留下的，不是更多互动次数，而是一个很小、很可靠的结果：当我回来，我知道从哪里继续。

## 约六页逐页内容

### 1 / Attention Is All You Need（0:00–0:25）

**主句**：AI可以生成更多，我想让人更容易继续。

屏幕只放标题、副题“把下一步留在手边”和问题“回来后，我刚才做到哪？”；不放脑部、波形或专注分数。

我讲：标题是隐喻；我要解决中断后重建上下文的具体问题。页脚小字标“产品机制提案”。

### 2 / 一次中断，丢掉的是继续的位置（0:25–0:55）

屏幕示例：修登录问题 → 已复现401 → 暂时离开 → 回来翻会话、找验证点。标“虚构场景”。

我讲：第一批用户是多上下文工作的开发者和创作者；首轮聚焦有准备的中断，不推断所有走神。研究入口放[2003准备实验](https://doi.org/10.1016/S1071-5819(03)00023-5)，标“机制依据，非产品效果”。

### 3 / 留一句，回来接一步（0:55–1:35）

屏幕流程：我选上下文 → Agent整理 → 我确认 → 保存 → 主动取回 → 回原任务。

示例卡：停点“已复现401”；下一步“重放过期登录案例”；完成条件“记下是否出现明确提示”。底部“拟补最小闭环；手动输入；不自动读电脑”。

我讲：Agent处理语义与缺项，用户控制结果；硬件读取确认卡不需要再调模型。不为每次点击生成内容。

### 4 / 两个增量，分别证明（1:35–2:10）

屏幕两列：Agent＝整理是否省事？硬件＝取回是否顺手？下面写“表单 / 快捷键 / 手机 / 普通EDC都是有效对照”。

我讲：复杂上下文才值得模型参与；桌前键鼠可能更好。默认静默、明确退出、无点击评分。图形只用简单卡片与箭头，像素角色作为可选状态角标。

### 5 / 已有、拟补、以后（2:10–2:35）

| 已有证据 | 拟补最小实现 | 未来愿景 |
|---|---|---|
| 像素软件基础；主机测试；合成摘要下真实模型调用 | 用户输入、确认卡持久化、设备收卡与主动取回 | 逐项授权的上下文连接器、支线处理、无线随身 |

我讲：现有调用不等于任务Agent，构建不等于实机。当前没有新机制效果数据。上台前按验收证据更新此页，未验证保持原标注。

### 6 / 我想证明：回来更快，工具更少打扰（2:35–3:00）

屏幕四个结果：恢复有效动作耗时 / 非必要切换 / 任务质量 / 建卡与使用负担。

我讲：分别比较有无Agent、有无硬件；若便签一样好就简化。落句“当我回来，我知道从哪里继续”。不展示虚构增长、评分、用户数或留存。
