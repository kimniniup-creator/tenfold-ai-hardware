# 80秒演示与尖锐问答

## 当前可用的概念演示（无需新功能）

这段在材料未实现时也能讲，但必须全程标“交互概念演示”。使用本页的文本卡或打印卡讲解，不拿点击旧宠物后播放新卡的方式伪装联动。当前未验证实机，不要求占用串口；旧版主机调用只有工程证据，不充当任务恢复Demo。

| 时间 | 我做什么 | 我说什么/评委看到什么 |
|---|---|---|
| 0–12秒 | 展示虚构登录任务与原始停点 | “我已经复现401，但还没检查提示。这是演示任务。” |
| 12–28秒 | 展示输入字段与一张事先写好的候选卡 | “我主动留下停点。这里展示的是拟议输出，不是现场模型生成。” |
| 28–40秒 | 指出来源、下一步及确认按钮位置 | “我确认以后它才成为恢复卡。Agent不能替我宣布已经做完。” |
| 40–53秒 | 做离开/返回的情境动作；拿起设备或示意物，不声称通信 | “回来时，我希望用这个固定入口取回卡。设备接卡是待补功能。” |
| 53–68秒 | 展示短卡“重放过期登录案例”；手动回到示例文档 | “下一步够清楚，我可以直接继续；全文和原任务入口仍在主机。” |
| 68–80秒 | 展示离线/无卡两张状态卡 | “断网读已保存卡，没存成功就明确说没存成功。接下来测恢复速度和额外负担。” |

概念卡（手写示例，不是生成结果）：

> 停点：已复现401，尚未检查过期登录时的提示。
> 下一步：重放过期登录案例，记录提示文字。
> 完成条件：明确记录是否出现可理解的错误提示。
> 来源：用户停点 S1；未检查：代码实际行为。

## 最小实现验收后才启用的80秒实机版

先决条件：owner提供固定版本、真实输入→候选→确认→主机持久化→设备ACK→物理取回→可见卡证据；离线重启读卡、B取消、旧回复失效通过。缺任何一项，回到概念版，或清楚标出软件/模拟设备Demo。

| 时间 | 动作与可观察结果 |
|---|---|
| 0–15秒 | 在主机输入上述虚构文本，展示将提交的字段；我说“只读我给的这段” |
| 15–30秒 | 发起真实生成，来源标签显示“云生成/手填/预录”之一。8秒超时切手填，现场说出失败；绝不偷偷放缓存冒充现场调用 |
| 30–42秒 | 我编辑或确认候选；先看到主机已保存，再看到设备已保存的ACK。未ACK就不进入“设备成功”叙事 |
| 42–57秒 | 退出卡，模拟一段中断；回来用专用动作取回。普通按压不得生成任务事件 |
| 57–70秒 | 我读短卡，主动回原任务执行一个示例动作。打开文档不等于已提高专注，讲解只到动作可继续 |
| 70–80秒 | 断网读缓存或按B取消；我说“这个闭环可运行，效果还需要对照实验” |

现场若延迟超出窗口，不加速假装成功。设备未连接：显示“主机版演示”；模型失败：标“手填卡”；取回失败：展示实际错误并终止该段。预录视频必须写明版本、录制时间和“预录”，不能当现场操作。没有震动部件不描述震动。

## 评委问答（Kim第一人称）

**为什么一定要硬件，为什么不是键鼠？**

我不认为一定要。键鼠在桌前很可能更快。硬件要证明的是固定入口、离开键鼠后的取回，以及是否少进一次任务/消息界面。USB版只验证桌旁，不证明随身性。若普通物件加快捷键同样好，我会先保留软件，不为外壳辩护。

**为什么是Agent，不是计时器或便签？**

计时器解决时间边界，便签已经可以保存下一步。Agent只在上下文零散、有冲突或缺信息时尝试减少整理负担；它提出有来源的卡、等待确认、保存版本、接受纠正。短文本不需要模型。若实验发现手填一样快、一样准，我会取消这部分推理。

**你说Agent，但不自主执行，算什么Agent？**

我做的是工具受限的任务辅助：根据给定上下文决定是否澄清、生成候选，并在确认后调用本地保存和取回工具；权限和状态由确定性代码约束。它不需要拥有全电脑权限。若交付只有一轮改写，我会叫它AI辅助，而不会宣称完整Agent闭环。

**如何证明用户更专注？**

我现在不能证明。我会测中断结束到第一个正确任务动作的时间，也把建卡时间算进去；同时检查任务质量、非必要切换与负担。单纯多坐十分钟、按很多次或喜欢角色，都不算专注提高。

**点击多就是分心吗？**

不是。点击可能是把玩、习惯或操作请求，工作类型也会改变频率。我只把专用动作当明确意图，不由次数判断注意力、压力或心情。普通把玩不会触发任务生成或专注评分。

**为什么它不会变成一个新干扰？**

它有这个风险，所以默认安静、由我主动取回，不自动轮播，不按频率弹建议；像素角色只作可关的状态反馈。实验单独记设备引起的抬眼和任务切换。如果为了看它而多分心，就失败，不能用“更有趣”抵消。

**从第一次使用到退出，完整链路是什么？**

我在主机选一个任务，填停点和下一步线索；选择是否云整理；编辑确认卡；核对保存和设备接收；中断后主动取回；手动回原任务。卡过时可以修订，没卡可以直接工作，B可关闭显示，主机可结束会话和删除本地记录。不强迫每天录入或补打卡。

**突然被打断，根本来不及输入怎么办？**

这正是首版边界。我只能给最近一次确认卡并标时间，不能声称知道最新停点。没有卡就没有。首批先测有准备的中断，后续才研究用户授权的上下文采集。

**EDC与注意力有什么科学关系？**

目前我把它当设计假设。已有把玩和安慰物研究能提示携带、触感和低负担的重要性，但没有验证这款设备提升专注。研究中断准备和意图外置，是为了选一个可测试机制，不是给EDC贴科学背书。

**“Attention Is All You Need”是不是混淆Transformer？**

我借用标题表达人的注意力值得被认真设计。原论文讨论模型架构，与人的注意力不是同一概念，我不会用它证明产品效果。

**你现在到底做出来了什么？**

已有像素互动软件基础、构建与主机测试，也有合成节奏输入下的真实模型调用记录。任务书签、任务文本同步和真实设备恢复闭环仍需补齐验收；此刻展示的是机制提案。上台前只按真实证据更新这一句。

**这跟旧十日环的封存恢复有什么不同？**

我借鉴“留下下一步”，但不恢复十日周期、日珠、强制收工或每天完成一次。这里的单位是一次工作中断，价值指标是恢复与负担，不是周期完成率。不能因为旧版有封存就说当前像素版已经有任务书签。

**模型幻觉、隐私和断网怎么办？**

只发送我选择的字段，卡的事实带来源；没给的信息写未知。草稿须我确认，模型不执行外部任务。断网手填、缓存取回；设备未保存不能显示已保存。所有这些是拟补规则，真实实现逐项验收。

**如果指标没有提升呢？**

Agent没有减少负担就改用模板；硬件不优于快捷键就退回软件；卡本身也没帮助，就停止这个机制。我想保留的是可重复的用户价值，不是必须保住每个技术部件。
